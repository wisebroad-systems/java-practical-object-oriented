# 第2章 end：一覧を変更できない形で公開する

第2章の終了時点のコードです。`getItems()`は、内部のリストをコピーし、変更できない形にして返します。

## 実行する

このディレクトリ（`chapter02/end`）で、次のコマンドを実行します。

```powershell
javac -encoding UTF-8 -d out src/main/java/*.java
java -cp out Main
```

コンパイルされるファイルは、`MenuItem.java`・`Order.java`・`Main.java`・`RejectionExamples.java`の4つです。

## 期待する結果

```text
注文確認：2000円
確定済み：true
コーヒー
コーヒー
ハンバーグ
```

拒否する操作の確認は、同じディレクトリで次のコマンドを実行します（コンパイルは上と同じです）。

```powershell
java -cp out RejectionExamples
```

```text
空の注文：空の注文は確定できません
料理数：0、合計：0円、確定済み：false
確定後の追加：確定後は料理を追加できません
料理数：1、合計：400円、確定済み：true
再確定：注文はすでに確定しています
料理数：1、合計：400円、確定済み：true
リスト経由の変更：変更できません
料理数：1、合計：400円、確定済み：true
```

## この段階で成り立つルール

- メニュー項目は名前と価格を持ちます。価格は0円以上で、負の価格は作成時に拒否します。
- 名前が`null`・空文字・空白だけのメニュー項目は、作成時に拒否します。
- 料理がない注文は確定できません。0円の料理だけの注文は確定できます。
- 確定済みの注文は、もう一度確定できません。
- 確定後は、`addItem()`で料理を追加できません。
- `null`の料理は追加できません。
- 拒否した操作の後も、注文の内容と状態は変わりません。
- `getItems()`が返す一覧は変更できません（変更しようとすると`UnsupportedOperationException`）。
- 取得済みの一覧は、後の追加に追従しません。最新の内容は、もう一度`getItems()`で取得します。

この段階は、次の章や段階で直す前の状態です。次の問題は、不具合ではなく、本文で考えるための題材として残しています。

# 第1章 start：同じ計算が2か所にある

第1章の開始時点のコードです。会計表示と注文確認の両方で、呼び出し側が注文の料理を取り出して合計を計算しています。

## 実行する

このディレクトリ（`chapter01/start`）で、次のコマンドを実行します。

```powershell
javac -encoding UTF-8 -d out src/main/java/*.java
java -cp out Main
```

コンパイルされるファイルは、`MenuItem.java`・`Order.java`・`Main.java`の3つです。

## 期待する結果

```text
会計：2000円
注文確認：2000円
```

コーヒー400円が2つとハンバーグ1,200円で、どちらも2,000円です。

## この段階で成り立つルール

- メニュー項目は名前と価格を持ちます。価格は0円以上で、負の価格は作成時に拒否します。
- 名前が`null`・空文字・空白だけのメニュー項目は、作成時に拒否します。

## 意図的に残している問題

この段階は、第1章で直す前の状態です。次の問題は、不具合ではなく、本文で考えるための題材として残しています。

- `Main`の`showBill`と`showOrderConfirmation`に、同じ合計の計算が書かれています。
- 呼び出し側が、注文の中身の持ち方（料理のリスト）と、合計の求め方を知っています。
- `getItems()`が注文の内部のリストをそのまま返すため、外から注文の中身を変えられます（第2章で扱います）。

# 第3章 step：明細と数量を導入する

第3章の途中段階のコードです。料理と数量のまとまりを明細（`OrderItem`）として表し、`addItem()`で数量を指定できるようにしました。ただし、明細の小計は、まだ注文が計算しています。

## 実行する

このディレクトリ（`chapter03/step`）で、次のコマンドを実行します。

```powershell
javac -encoding UTF-8 -d out src/main/java/*.java
java -cp out Main
```

コンパイルされるファイルは、`MenuItem.java`・`OrderItem.java`・`Order.java`・`Main.java`の4つです。

## 期待する結果

```text
コーヒー × 2
ハンバーグ × 1
合計：2000円
確定済み：true
```

## この段階で成り立つルール

- メニュー項目は名前と価格を持ちます。価格は0円以上で、負の価格は作成時に拒否します。
- 名前が`null`・空文字・空白だけのメニュー項目は、作成時に拒否します。
- 明細の数量は1以上です。数量が0や負の明細、料理が`null`の明細は作れません。
- 同じ料理を後から追加すると、別の明細になります（明細はまとめません）。
- 料理がない注文は確定できません。0円の料理だけの注文は確定できます。
- 確定済みの注文は、もう一度確定できません。
- 確定後は、`addItem()`で料理を追加できません。
- `getItems()`が返す一覧は変更できません。

## 意図的に残している問題

この段階は、次の章や段階で直す前の状態です。次の問題は、不具合ではなく、本文で考えるための題材として残しています。

- 注文の`totalPrice()`が、明細ごとの料理の価格と数量を取り出して、小計を自分で計算しています。
